# Documentation index — what is where

Start with **`START-HERE.md`**, then **`HANDOVER.md`**. This page lists every folder and
document in this repository.

---

## 1. The folders

| Folder | What it contains | Who uses it |
|--------|------------------|-------------|
| `install/` | The installer (`install.sh`), the Docker setup, the database tables and security rules, helper scripts | The person installing and running the server |
| `ios-app/` | The **Instant iPhone app** (the supported customer app) | The person building the app for iPhones |
| `backend/` | The **API**: customer sessions and 3D model storage | Built and run by the installer |
| `expert-web/` | The **web console**: login, customer sign-up page, creating expert accounts, uploading 3D models, live sessions | Built and run by the installer |
| `android-app/` | Android version of the customer app — **reference only, not supported yet** | Developers who want to port it |
| `scripts/` | `glb_to_usdz.py`: converts a 3D model to USDZ | Whoever prepares 3D models |

## 2. How the system behaves

| Topic | Behaviour |
|-------|-----------|
| Sign-in | Email and password |
| Admin | Created during install: you type the username (an email) and password |
| Customers | Anyone who signs up — in the iPhone app or on the web `/signup` page. Always a customer |
| Experts | Created by the admin in the web console |
| 3D models | The admin uploads `.usdz` files in the web console |
| Where it runs | Your server: either a public domain with HTTPS, or your local network |
| Keys and passwords | All generated by the installer; none are built in |

## 5. Status

The server setup was statically checked (Docker configuration parses, scripts pass a syntax
check, the key generation was verified, the API and web console type-check, the iPhone app
compiles). A full install on a clean server is best done together with your contact the first
time; `HANDOVER.md` Part 8 lists the most likely snags. The Android app is not built or tested.
